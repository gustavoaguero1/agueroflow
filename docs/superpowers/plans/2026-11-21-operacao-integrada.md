# Operação Integrada — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Turn AgueroFlow's isolated modules into one operational flow an owner can judge: every NF-e issued against the company CNPJ lands in the system automatically, the user only classifies it, and stock, payables and costs update by themselves; plus a cross-module pending-items panel, a real sales funnel that spawns work orders, safe stock movements, removal of fake data, and a WhatsApp agent that answers from real ERP data.

**Architecture:** Server (firebase-admin, already wired with auth) owns NF-e ingestion (XML upload + SEFAZ Distribuição DF-e with the company's A1 certificate) and writes `nfe_documents`. The browser classifies notes; a single shared stock service (Firestore transaction) is used by Stock and by NF-e classification. A new Finance module holds payables and a chart of accounts. Everything is org-scoped by `orgId` and covered by the existing Firestore rules pattern.

**Tech Stack:** Express + firebase-admin, React 19, Firebase JS SDK, `fast-xml-parser` (promote from transitive to direct dependency), Node `https` with PFX for SEFAZ mTLS, Node `crypto` for XML-DSig, `node:test`.

**Spec:** this plan is its own spec (owner asked to "just do it"); the audit in `docs/superpowers/analise/2026-11-20-auditoria-modulos.md` is the background. Owner request (verbatim intent): "toda nota emitida no CNPJ da empresa já aparecer lá… separando por material, estoque, quantidade, o custo já vai para o financeiro, e fica para o usuário só categorizar e colocar um tipo de custo". Bank integration: later, out of scope.

## Global Constraints
- Branch `claude/epic-gates-86iss1`; AI Studio edits `main` in parallel → prefer new files; surgical edits elsewhere.
- Every new collection carries `orgId`, gets an explicit block in `firestore.rules` (members of the org read/write; server-only fields enforced where noted) and rules tests in `tests/emulator/rules.test.ts`. Never `if true`.
- Server routes go under `/api/...` behind the existing `requireAuth`; mutations that touch money or certificates use `requireRole('Admin','Gerente')`; org from `req.orgId`/claims, never body.
- Secrets only via env: `NFE_CERT_PFX_BASE64`, `NFE_CERT_PASSWORD`, `NFE_CNPJ`, `NFE_UF` (IBGE code, e.g. 35), `NFE_AMBIENTE` (`1` produção, `2` homologação; default `2`), `NFE_ORG_ID` (org that owns the CNPJ). Document in `.env.example` and `docs/hospedagem-credenciais.md`.
- Money as numbers in BRL with 2 decimals; quantities as numbers; dates ISO strings.
- UI in Portuguese, following existing component styles (Tailwind classes and lucide icons as the surrounding module uses). Navigation additions go into `src/components/layout/AppLayout.tsx` + `src/App.tsx` following existing patterns.
- No fabricated/demo data in production paths. No seeds on module open.
- Tests: `npm test` (unit, `tests/*.test.ts`), `npm run test:emulator` (`tests/emulator/*.test.ts`), `npm run lint` 0 errors. Clean up processes/data files after manual runs.

## Review Focus
1. Same NF-e imported twice (upload + SEFAZ, or two uploads) → one document (key = chave de acesso), never duplicated stock or payables.
2. Classifying an NF-e twice / double-click → stock enters once, payables created once (transaction + status guard).
3. NF-e whose destinatário CNPJ isn't the company's → rejected with a clear message (not silently imported).
4. SEFAZ returns cStat 137 (nada a retornar) or 656 (consumo indevido) → backs off ≥ 1 hour, keeps `ultNSU`, never hammers SEFAZ.
5. Stock outflow concurrent with another outflow → never goes negative (transaction).

### Task 1: NF-e parser and import endpoint
**Files:** Create `server/nfe/parseNfe.ts`, `server/nfe/nfeStore.ts`, `tests/parseNfe.test.ts`, `tests/emulator/nfeStore.test.ts`, `tests/fixtures/nfe-sample.xml`; Modify `server.ts` (mount router), `package.json` (fast-xml-parser direct dep).
**Interfaces (produces):**
- `parseNfeXml(xml: string): ParsedNfe` — accepts `nfeProc` or bare `NFe`. `ParsedNfe = { chave: string; numero: string; serie: string; modelo: string; emitidaEm: string; emitente: { cnpj: string; nome: string; uf?: string }; destinatario: { cnpj: string; nome: string }; valorTotal: number; valorProdutos: number; valorFrete: number; valorIcms: number; valorIpi: number; itens: NfeItem[]; duplicatas: { numero: string; vencimento: string; valor: number }[]; naturezaOperacao: string }`, `NfeItem = { n: number; codigo: string; descricao: string; ncm: string; cfop: string; unidade: string; quantidade: number; valorUnitario: number; valorTotal: number; ean?: string }`. Throws `Error('XML não é uma NF-e válida')` when `infNFe` missing; chave = `infNFe@Id` without `NFe` prefix (44 digits).
- `upsertNfe(h: AdminHandles, orgId: string, parsed: ParsedNfe, source: 'upload'|'sefaz', xml?: string): Promise<{ id: string; created: boolean }>` → doc `nfe_documents/{orgId}_{chave}` with `{ orgId, ...parsed, status: 'aguardando_classificacao', source, recebidaEm, xmlPath? }`; existing doc → `created:false`, never resets status. Full XML saved to bucket `nfe-xml/{orgId}/{chave}.xml`.
- `upsertNfeSummary(h, orgId, resumo: { chave; emitente: {cnpj; nome}; valorTotal; emitidaEm; situacao }): Promise<...>` → same doc id with `status: 'resumo'` only if doc doesn't exist (full XML later upgrades it: `upsertNfe` on a `resumo` doc replaces fields and sets `aguardando_classificacao`).
- `POST /api/nfe/import` (requireRole Admin/Gerente; JSON `{ files: [{ name, content }] }` with XML text) → `{ results: [{ name, ok, chave?, created?, error? }] }`. Validates `destinatario.cnpj` against `organizations/{orgId}.cnpj` (digits only); mismatch → `ok:false, error:'Nota não emitida para o CNPJ da empresa (…)'`.

### Task 2: SEFAZ Distribuição DF-e auto-fetch + Ciência da Operação
**Files:** Create `server/nfe/sefaz.ts`, `server/nfe/xmlSign.ts`, `server/nfe/nfeSync.ts`, `tests/xmlSign.test.ts`, `tests/sefazParse.test.ts`; Modify `server.ts` (start sync + route), `.env.example`, `docs/hospedagem-credenciais.md`.
**Interfaces:**
- `distDfeRequest(cfg, ultNSU: string): Promise<{ cStat: string; xMotivo: string; ultNSU: string; maxNSU: string; docs: { nsu: string; schema: string; xml: string }[] }>` — SOAP 1.2 to `https://www1.nfe.fazenda.gov.br/NFeDistribuicaoDFe/NFeDistribuicaoDFe.asmx` (homologação `https://hom1.nfe.fazenda.gov.br/...`), body `distDFeInt` versão `1.01` (`tpAmb`, `cUFAutor`, `CNPJ`, `distNSU/ultNSU`), mTLS via `https.Agent({ pfx, passphrase })`; `docZip` = base64 gzip → `zlib.gunzipSync`.
- `parseDistResponse(xml: string)` (pure, unit-tested with a fixture).
- `signEvent(xmlEvento: string, pfx: Buffer, passphrase: string): string` — enveloped XML-DSig over `infEvento` (RSA-SHA1, C14N 1.0, transforms enveloped-signature + c14n, X509Certificate), using `crypto` + PKCS#12 parsing: if Node can't read PFX into PEM key/cert without a dependency, add `node-forge` (already transitive? check) as direct dependency — only for PKCS#12 extraction.
- `sendCiencia(cfg, chave: string): Promise<{ cStat: string; xMotivo: string }>` — evento 210210 to RecepcaoEvento (`https://www.nfe.fazenda.gov.br/NFeRecepcaoEvento4/NFeRecepcaoEvento4.asmx`, AN, cOrgao 91).
- `runNfeSync(h): Promise<{ fetched: number; summaries: number; full: number; ciencia: number; nextRunAt: string }>` — loop distNSU until `ultNSU == maxNSU` (max 20 calls/run); `resNFe` → `upsertNfeSummary` + `sendCiencia` (once per chave, tracked in doc field `cienciaEnviadaEm`); `procNFe` → `upsertNfe(source:'sefaz')`; state in `nfe_sync/{orgId}` `{ ultNSU, lastRunAt, nextRunAt, lastStatus }`. cStat 137/656 → `nextRunAt = now + 61min` (Review Focus 4). Scheduler: `setInterval` 5 min that runs only when `now >= nextRunAt` and NFE env is set; route `POST /api/nfe/sync-now` (Admin/Gerente) honours `nextRunAt` too (returns `{ skipped:true, nextRunAt }`). Disabled cleanly when env missing.
- [ ] Failing tests: `parseDistResponse decodes docZip and lists schemas`, `cStat 137 schedules backoff`, `signEvent produces verifiable signature` (sign with a test PFX generated in the test via node-forge or a committed test-only PFX; verify SignatureValue with `crypto.verify` over the canonicalized SignedInfo and DigestValue over canonicalized infEvento), `sync skips before nextRunAt`.
